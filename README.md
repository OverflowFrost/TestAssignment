# Накопление материала на поверхности (Unity)

Тестовое задание: механика накопления материала на плоской поверхности с изменением геометрии Mesh.

Полусферическая зона перемещается по поверхности. Пока зажат пробел, внутри зоны материал нарастает снизу вверх. Зона оставляет непрерывный объёмный след, повторные и пересекающиеся проходы суммируются в общей геометрии.

## Запуск

- Версия Unity: `2021.3.15f1`
- Сцена: `Assets/Scenes/SampleScene.unity`
- Проект использует классический `UnityEngine.Input`: в Project Settings → Player → Active Input Handling должно быть `Input Manager (Old)` или `Both`.

## Управление

| Клавиша | Действие |
|---|---|
| `W` `A` `S` `D` | перемещение зоны по поверхности |
| `Space` (удерживать) | накопление материала |
| `Caps Lock` (удерживать) | 	копание: зона углубляет поверхность (дополнительный режим, не входит в задание) |
| `R` | сброс поверхности |

## Настройки в Inspector

**AccumulationTool** (зона воздействия):

| Параметр | По умолчанию | Описание |
|---|---|---|
| Move Speed | 5 | скорость перемещения зоны |
| Base Radius | 2 | базовый радиус |
| Radius Amplitude | 0.75 | амплитуда изменения радиуса |
| Radius Frequency | 0.5 | частота изменения радиуса, циклов в секунду |
| Radius Curve | EaseInOut | `AnimationCurve` изменения радиуса |

**AccumulationSurface** (поверхность):

| Параметр | По умолчанию | Описание |
|---|---|---|
| Resolution X / Z | 160 | число вершин сетки по осям |
| Size X / Z | 20 | размер поверхности в мировых единицах |
| Accumulation Speed | 0.8 | скорость вертикального роста, ед./с |
| Max Samples Per Frame | 96 | ограничение числа точек выборки траектории на кадр |

Радиус считается так: `радиус = Base Radius + (значение кривой × 2 − 1) × Amplitude`. Значение кривой берётся в точке цикла `(время × частота) mod 1`. Кривая должна идти в диапазоне 0..1. Чтобы радиус менялся без скачка при начале нового цикла, значения кривой в начале и в конце должны совпадать (например, 0 → 1 → 0).

## Как устроено

| Компонент | Ответственность |
|---|---|
| `AccumulationSurface` | сетка высот, построение и обновление Mesh, алгоритм добавления материала, сброс |
| `AccumulationTool` | ввод WASD и пробела, перемещение зоны, радиус по кривой, визуал зоны |
| `ResetSurfaceKey` | сброс поверхности по клавише `R` |

### Хранение материала

Накопленный материал хранится в массиве `float[] heights`: по одному значению высоты на вершину регулярной сетки (height map). Индекс вершины `z * resolutionX + x`. Массив не зависит от объекта `Mesh`: Mesh служит только для отображения. Массив `vertices` является рабочей копией для загрузки в Mesh, его координата `y` повторяет `heights`.

### Обновление Mesh

- Топология (индексы треугольников, UV) строится один раз при старте. Для сеток больше 65535 вершин включается 32-битный формат индексов, Mesh помечается `MarkDynamic()`.
- Алгоритм изменяет только `heights` и `vertices[i].y` и поднимает флаг `dirty`.
- В конце кадра, если флаг поднят, вершины одним вызовом записываются в Mesh (`mesh.vertices = vertices`), затем пересчитываются нормали и границы. Если ничего не менялось, Mesh не трогается.

### Алгоритм накопления

1. Позиция зоны на кадре сравнивается с позицией на прошлом кадре, получается отрезок `prev → curr`.
2. Отрезок делится на `N = ceil(длина / (0.5 × шаг сетки))` точек выборки (не более `Max Samples Per Frame`, не менее 1). Выборка идёт по серединам подинтервалов, поэтому каждая точка траектории учитывается один раз.
3. Время кадра `dt` делится поровну между точками: каждая получает `dt / N`. Благодаря этому вершина под зоной получает `скорость × время под зоной` независимо от FPS. При низком FPS отрезок длиннее и точек больше, но на каждую приходится пропорционально меньше времени.
4. Для каждой точки перебираются только вершины внутри квадрата, описанного вокруг круга радиуса `r` (а не вся сетка).
5. Для вершины на расстоянии `d` от центра высота купола равна `sqrt(r² − d²)`. Если текущая высота ниже купола, она растёт: `h = min(купол, h + скорость × dt / N)`. Иначе вершина не меняется.

Условие «растём только вверх до купола» гарантирует, что смена радиуса и перемещение зоны никогда не уменьшают накопленный материал: полусфера ограничивает только добавление нового. Все проходы пишут в один массив, поэтому повторные и пересекающиеся проходы суммируются.

### Аллокации

Все массивы (`vertices`, `triangles`, `uvs`, `heights`) создаются один раз при старте. В `Update` нет `new`, LINQ, списков и корутин, поэтому постоянных аллокаций при непрерывной работе нет.

## Ограничения решения

- **Дискретность.** Форма следа задаётся только вершинами сетки: при шаге около 0,13 ед. и малом радиусе зона получает мало вершин, край купола выглядит ступенчатым. Качество зависит от `Resolution`.
- **Height map.** Поверхность описывается одной высотой на точку, поэтому нависающие формы и пустоты невозможны.
- **Стоимость обновления Mesh.** При любом изменении в Mesh загружается весь массив вершин и пересчитываются нормали всей поверхности, это O(число вершин). Решение плохо масштабируется на очень большие сетки.
- **Предел выборки.** При очень высокой скорости или очень низком FPS число точек может упереться в `Max Samples Per Frame`: суммарная скорость накопления сохраняется, но покрытие траектории становится разреженным и возможны разрывы.
- **Масштаб.** Радиус и высоты считаются в мировых единицах, поэтому у объекта поверхности должен быть масштаб `(1, 1, 1)`.
- **Материал не сохраняется как объём.** Высота ограничена куполом, а не расходуется из ограниченного запаса; материал не осыпается и не растекается.
- **Ввод.** Используется старый Input Manager, новая Input System не поддерживается.
- **Однопоточность.** Вся работа выполняется на главном потоке CPU.

## Предложения по улучшению

- Вынести состояние в отдельный класс `HeightField` (данные и алгоритм) и оставить в `AccumulationSurface` только отображение. Сейчас данные и Mesh живут в одном классе.
- Отслеживать изменённый прямоугольник (dirty rect): пересчитывать нормали и загружать в Mesh только его (`Mesh.SetVertexBufferData` с диапазоном), нормали считать центральными разностями по height map.
- Перенести накопление в Jobs + Burst или на GPU: height map как `RenderTexture`, смещение вершин в шейдере, тогда загрузка Mesh не нужна вовсе.
- Разбить поверхность на чанки с независимыми флагами обновления для больших площадей.
- Вынести форму кисти в интерфейс (`IBrush`) и стратегию ввода в отдельный компонент: проще добавить другие формы и новую Input System.
- Добавить осыпание материала по углу естественного откоса и сохранение объёма.
- Окраска по высоте или по времени накопления (vertex colors / шейдер) для более читаемого рельефа.
- Режим копания (удаление материала) отдельной кистью, не затрагивающей основную механику.
- EditMode-тесты: материал не убывает, накопление не зависит от FPS, сброс обнуляет поверхность.
- Адаптивный шаг выборки траектории в зависимости от радиуса и сохранение/загрузка height map.
